# سوئد یدک — بسته آماده استقرار Render + Neon

## محتویات و تغییرات
- اتصال آنلاین به PostgreSQL از طریق متغیر محیطی `DATABASE_URL` (Neon).
- نگه‌داشتن حالت SQLite برای اجرای محلی/آفلاین؛ وقتی `DATABASE_URL` تنظیم نباشد، برنامه از `database.db` استفاده می‌کند.
- افزودن دکمه «دانلود کپی کامل دیتابیس برای نسخه آفلاین» در صفحه پشتیبان‌گیری؛ فایل دانلودی SQLite است.
- افزودن فرم بازیابی فایل `.db` به Neon (فقط مدیر سیستم). بازیابی، داده‌های جداول موجود در فایل را جایگزین می‌کند؛ پیش از آن حتماً پشتیبان دانلود شود.
- زمان‌های جدید بر اساس منطقه زمانی مرورگری که صفحه را باز کرده است محاسبه می‌شود.
- اجرای برنامه با Gunicorn و پورت تخصیص‌یافته Render.

## استقرار در GitHub و Render
1. محتوای این پوشه را در یک مخزن GitHub بارگذاری کنید.
2. در Render یک Web Service از مخزن بسازید. Build Command: `pip install -r requirements.txt` و Start Command: `gunicorn app23:app`.
3. در Neon یک دیتابیس PostgreSQL بسازید و رشته اتصال را کپی کنید. در Render → Environment متغیرهای زیر را اضافه کنید:
   - `DATABASE_URL`: رشته اتصال PostgreSQL/Neon (ترجیحاً pooled connection string همراه `sslmode=require`).
   - `SECRET_KEY`: یک مقدار تصادفی طولانی.
   - `DEFAULT_ADMIN_PASSWORD`: رمز اولیه قوی برای مدیر.
4. Deploy کنید. جداول در اولین راه‌اندازی ساخته می‌شوند.
5. برای ورود اولیه نام کاربری `admin` و رمزی که در `DEFAULT_ADMIN_PASSWORD` تعیین کرده‌اید استفاده شود. اگر این متغیر تنظیم نشود، مقدار پیش‌فرض قدیمی `123456` خواهد بود؛ حتماً آن را تغییر دهید.

## اجرای محلی / آفلاین
- پایتون 3.11 نصب باشد.
- `pip install -r requirements.txt`
- متغیر محیطی `DATABASE_URL` را حذف/خالی کنید.
- فایل پشتیبان دانلودشده را در کنار `app23.py` با نام `database.db` قرار دهید.
- اجرا: `python app23.py`

## نکات مهم قبل از استفاده واقعی
- فایل `database.db` اولیه در اختیار ما نبود؛ بنابراین اطلاعات قدیمی شما به Neon منتقل نشده است. این نسخه ساختار جداول را ایجاد می‌کند و می‌توانید پس از Deploy، از مسیر پشتیبان‌گیری فایل SQLite قدیمی را با گزینه بازیابی به Neon وارد کنید.
- این بسته از نظر نحوی با `py_compile` بررسی شده است؛ اتصال زنده به Neon و آزمون کامل همه عملیات فروش/خرید بدون رشته اتصال و داده واقعی امکان‌پذیر نبود. ابتدا روی یک دیتابیس آزمایشی Neon تست کنید.
- هنگام استفاده از Neon، گزینه‌های کپی مستقیم روی فلش از سمت سرور Render کار نمی‌کنند؛ فایل پشتیبان را دانلود کنید و سپس در کامپیوتر/موبایل روی فلش ذخیره کنید.
- فایل `database.db` یا رمزهای واقعی را در GitHub بارگذاری نکنید.
- بکاپ SQLite خروجی برای سازگاری با نسخه آفلاین طراحی شده است. قبل از هر بازیابی، از دیتابیس مقصد نیز نسخه پشتیبان بگیرید.
